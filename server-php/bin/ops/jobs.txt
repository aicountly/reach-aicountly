# Scheduled jobs of Reach (E8-OPS, F160). Installed into the deploy user's crontab by the production deploy
# (.github/workflows/deploy-production.yml -> bin/ops/post-deploy-jobs.sh -> bin/ops/install-jobs.sh --apply); check on
# the server with `bash bin/ops/install-jobs.sh --check`. `php spark reach:console-audit-deliver` reports itself to
# Console's Cron Job Monitor (reach.console_audit_deliver; app/Libraries/CronHeartbeat.php, key CONSOLE_CRON_MONITOR_KEY
# in api/.env, written by the deploy from the repo secret), so it runs WITHOUT the run-job.php wrapper — wrapping it
# with --monitor would report every run twice.
# The worker / blog / community crons (docs/operations/REACH_WORKER_AND_CRON.md) are not listed here yet: they stay
# hand-installed, and a hand-installed line for them is left alone.
#! app: reach
# CodeIgniter on its Postgre driver: the PHP CLI needs pgsql (not pdo_pgsql).
#! php-ext: pgsql
# Replaces the hand-installed line README.md used to give, so the job never runs twice. The spark command name is
# Reach's own.
#! legacy-pattern: spark[[:space:]]+reach:console-audit-deliver
# name                  | schedule    | command (run from the api folder)
console-audit-deliver   | */5 * * * * | {php} spark reach:console-audit-deliver
